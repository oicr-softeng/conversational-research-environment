Tightened the renderer's hardening, so that nothing the page stores reaches disk and the browser refuses HTML from a string.

- `apps/desktop/src/main/rendererSession.ts`: the renderer's session is kept in memory, `renderer` in place of `persist:renderer`. Its local storage, IndexedDB and cache are never written to disk. State that must outlast a quit is the main process's to save, encrypted, per the MCP host plan's §2.4
- `apps/desktop/src/main/contentSecurityPolicy.ts`: the packaged policy adds `require-trusted-types-for 'script'` and `trusted-types 'none'`. Assigning a string to `innerHTML` or a similar sink throws, and no policy can be created, so a library that needs HTML must bring a named policy for review. Development builds do not enforce it, since `developmentPolicy` is unchanged
- Checked in the packaged app through Chromium's remote debugging protocol: the policy header carries both directives, and React renders with no violation. Assigning to `innerHTML` and calling `trustedTypes.createPolicy` both throw. A `localStorage` key and an IndexedDB database written before a quit are gone after relaunch
- Tests: the app's main process has 32, all passing
