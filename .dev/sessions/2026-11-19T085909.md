Upgraded `tsup` from 6.7 to 8.5.1 in both modules, since 6.7 kept `apps/desktop`'s Vite from being hoisted.

- `tsup` 6.7 brings `yaml` 1 to the root `node_modules`, through `postcss-load-config` 3. Vite's optional peer `yaml@^2` then keeps Vite nested in the app's workspace, while Forge's Vite plugin is hoisted to the root, where it cannot find Vite
- The `target: 'node24'` lines left both `tsup` configurations. They were needed only because the esbuild 0.17.19 bundled with `tsup` 6.7 refused `es2024`. `tsup` takes its target from the `tsconfig` base again, so it follows a Node move without its own change
- The lockfile changes only `tsup`'s own dependencies
- `npm audit` now lists one low-severity advisory, GHSA-g7r4-m6w7-qqqr, for the esbuild 0.27.7 under `tsup`. It concerns esbuild's development server on Windows, which `tsup` builds never start. Its fix, esbuild 0.28.1, is outside `tsup` 8.5.1's `^0.27.0` range
- Build, typecheck, lint and `prettier --check modules scripts` pass on Node 24.21.0. Tests: `mcp-client` 70 in 15 suites and host-core 192 in 43, all passing, as before. Both modules' runtime exports are unchanged in ESM and CommonJS. Their declarations now mark type-only exports with `type`, and each module gains an `index.d.cts` beside `index.d.ts`
